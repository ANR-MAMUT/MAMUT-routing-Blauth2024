# Changelog: Blauth2024 benchmark family

All notable changes to the Blauth2024 family are recorded here. The first entry records the creation of this repository. The section after it holds the changelog of the former repository. It keeps every entry, fact, date, count and commit reference, with the wording edited for style and the headings moved 2 levels down.

## 2026-11: family repository

- The family, kept until now in the repository `MAMUT-routing-TDVRPTW-Blauth2024`, becomes the repository `MAMUT-routing-Blauth2024`, mounted in MAMUT-routing at `benchmarks/Blauth2024`. The history of the former repository is imported under the directory of its problem type. `history/` holds the map from the former to the new commit identifiers.
- Instances and best-known solutions keep their former path after the problem type, for example `TDVRPTW/n=10/Blauth-berlin.vrp.json`.
- The 20 hosted ATF sidecars (n=10 and n=500) move to `sidecars/`, for example `sidecars/n=10/Blauth-berlin.atf.json.gz`. None is removed. In 40 instances the sidecar path field now holds a path relative to the repository root. No sidecar content changed, and the sidecar SHA-256 recorded in each instance is unchanged.
- The 20 instances of `n=1000` and `n=2000` reference sidecars that this repository does not ship. A user who regenerates them now places them at `sidecars/n=1000/<Name>.atf.json.gz` and `sidecars/n=2000/<Name>.atf.json.gz`, no longer next to the instance. The regeneration instructions in README.md are updated accordingly.
- The SHA-256 of the 40 instance files changed because of the rewritten path field. No instance identifier changed, and no best-known solution changed.
- `mamut-collection.json` at the root marks the repository as a family collection (`"layout_version": 2`).
- This layout is read by `mamut-routing-lib` 0.13 and later, which is in development and not released yet. `mamut-routing-lib` 0.12 and earlier read the former layout, which stays available read-only in the archived former repository.
- README, LICENSE, CHANGELOG and CITATION.cff move from `TDVRPTW/` to the root, and a NOTICE file is added. The `AUTHORS` file is removed. A `.gitignore` excludes the regenerated sidecar directories `sidecars/n=1000/` and `sidecars/n=2000/`.

## Former TDVRPTW repository

### Changelog of the Blauth2024 TDVRPTW BKS

All notable changes to the `Blauth2024` best-known solutions (BKS) are recorded here. Objective: **FleetCostDuration** (sum of per-route optimal durations plus `36000000 ms` per route, where the depot departure time of each route is a decision variable). Costs are the authoritative output of the canonical checker (`mamut_routing_lib.td.check_td_solution`, mamut-routing-lib >= 0.12.0, checker contract `td-fold/2`): exact IEEE-754 double arithmetic, no epsilon thresholds, routes in canonical order, total summed in that order, so any strict improvement is real. The upstream dollar objective is recovered exactly as `$ = cost_ms / 180000`.

#### 2026-09-24

**Checked under the `td-fold/2` checker contract (mamut-routing-lib 0.12.0): n=10 and n=500 unchanged, n=1000 and n=2000 pending.** mamut-routing-lib 0.12.0 replaces the TD checker's route fold (checker contract `td-fold/1` -> `td-fold/2`). Waiting and service at a vertex are now applied exactly to the accumulated arrival times instead of being composed through a ratio interpolation, and travel on slope-one pieces is computed by addition. `mamut-routing bks reprice-td` re-priced the 20 n=10 and n=500 BKS against their committed ATF sidecars: every cost, route duration and departure time is bit-identical under the new contract, and no file changed. The 20 n=1000 and n=2000 BKS could not be re-priced because their ATF sidecars are not hosted (see Hosting in README.md): they keep their `td-fold/1` values until the sidecars are next materialized and `mamut-routing bks reprice-td` is run on them, and any move will be recorded here. The checker requirement is now mamut-routing-lib >= 0.12.0.
